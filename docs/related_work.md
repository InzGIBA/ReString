# Обзор родственных проектов и алгоритмов string art

Зачем: сравнить ReString с тем, что делают другие генераторы (open source, академия,
художники), вытащить их «правила» — эмпирические константы, модели затемнения, критерии
остановки, трюки — и понять, что нам стоит перенять. Все факты проверены по первоисточникам
(README/код/PDF); ссылки в конце.

## 1. Пейзаж: от куда все растут

- **Petros Vrellis, «A new way to knit» (2016)** — художник, с которого всё началось:
  обод 28″ (711 мм), **200 гвоздей**, **одна непрерывная нить, 3000–4000 протяжек**,
  1–2 км нити, вручную по инструкциям от программы. Детали алгоритма не публиковал.
- **gist kaspermeerts (2016)** — канонический код, от которого ответвилась большая часть
  GitHub-проектов: жадный выбор хорды, `MAX_LINES=4000`, `N_PINS=288`, `MIN_DISTANCE=20`,
  `MIN_LOOP=20`, `LINE_WEIGHT=15`.
- **Birsak, Rist, Wonka, Musialski (Eurographics 2018)** — главная академическая работа:
  256 гвоздей на 630 мм, нить 0.15 мм → сетка 4096², бинарный least-squares с жадным
  add/remove-солвером, эйлеров путь для непрерывности, робот-намотка (типично ~5000
  витков / 2.5 км / ~2 ч).
- **Demoussel et al. (Bridges 2022)** — «жадный алгоритм для генеративного string art»:
  1000 гвоздей, и главное — **полупрозрачная нить (α=0.3) beats непрозрачная**: RMS
  −25–30% при ~2.4× числа нитей.
- Из open source подробно разобраны: **callummcdougall/computational-thread-art** (штрафы
  w⁺/w⁻, эйлеров путь), **Hirnmoder/thread-art** (мультипликативная модель, Гаусс-блюр
  нити, multiprecomputed all-pairs), **roy-hachnochi/string-art** (4 оптимизатора,
  мультиколор), **halfmonty/StringArtGenerator** (Go/WASM), **isandrocks/ThreadArt**
  (SSIM-остановка, edge-boost), **damione1/thread-art-generator** (CNC + G-code, 2
  алгоритма), **piellardj**, **prabinpebam**, **danielvarga** (LS-базлайн из статьи Birsak).
- Забавный факт: **kaspar98/StringArt** (прародитель этого репозитория) сам — часть этого
  ландшафта: жадный алгоритм, `-r ~50` random nails, отказ экспортировать порядок нитей
  в RGB «потому что аддитивная симуляция может не совпасть с реальностью».

Консенсус по физическим портретам: **гвоздей 180–360, нитей 3000–5000, нить 1–3 км,
чёрная по белому, холст 600–711 мм**. Диапазон пользователя (3000–7000) — это верх
консенсусной зоны; наши замеры насыщения жадного (3400–5700 улучшающих из 7000 итераций
на 211 гвоздях) ложатся ровно в него.

## 3. Их «правила» — что они себе ставят ограничениями

1. **Минимальная дистанция между гвоздями + кулдаун** — почти все запрещают короткие
   хорды и мгновенные возвраты (kaspermeerts `MIN_DISTANCE=20`; halfmonty 30 + исключение
   последних 20; damione1 circ-min 22 + cooldown 8; isandrocks 3–5). У ReString этого нет —
   жадный может тянуть нить на соседний гвоздь.
2. **Непрерывность нити для физической намотки.** Оптимизаторы, выбирающие произвольные
   хорды (Birsak, callummcdougall, damione1), дорисовывают рёбра и строят **эйлеров путь**
   (Hierholzer). У ReString последовательность непрерывна по построению (жадный всегда
   тянет от текущего гвоздя) — эйлеров постпроцессинг не нужен, наш `pull_order` готов к
   намотке как есть.
3. **Полупрозрачность/ослабление нити.** Demoussel: α=0.3 даёт −25–30% RMS при 2.4× нитей;
   Birsak: более тёмный вход (×0.5–0.7) аппроксимируется лучше. Это в точности наша
   находка из [quality_analysis.md](quality_analysis.md): экспортная сила `-s 0.05`
   (вдвое слабее рабочей) монотонно улучшает качество в диапазоне 3000–7000, тогда как
   дефолт 0.1 деградирует после ~2000.
4. **Клип-модель затемнения.** Birsak формализует: z = min(1, Σ нитей) — «слои поверх
   слоёв не темнее чёрного». У нас тот же `np.clip(0,1)`; possiblywrong считает темноту
   как долю чёрных субпикселей в блоке 16×16 (лучше, чем 8×8 у Birsak).
5. **Остановка по качеству, а не только по бюджету.** Семейство: Birsak — нет улучшающих
   add/remove; possiblywrong — лучшее улучшение отрицательно; isandrocks —
   **SSIM после Гаусс-блюра σ=2** (обратите внимание: блюр перед SSIM лечит ровно ту
   проблему тонких AA-линий, которую мы наблюдали — «SSIM пикирует на 50 нитях»);
   damione1 — 1000 неудач + **откат к лучшему префиксу** (у нас 3 неудачи подряд —
   заметно агрессивнее; и мы не откатываемся к лучшему состоянию).
6. **Важностные карты.** Birsak, Demoussel, McDougall, Medium-посты: умножать ошибку
   пикселя на вес (глаза/рот приоритетнее). У нас пока нет.
7. **Асимметричные штрафы.** McDougall: отдельные веса на недотемнение/перетемнение
   (сохраняют мелкие светлые детали — блики в глазах) + lightness_penalty, терпящий
   уход в темноту. У нас квадратичная симметричная ошибка.
8. **Edge-boost.** isandrocks: ошибка ×(1 + 2·Sobel) — нити «цепляются» за контуры.
9. **Случайное подсемплирование кандидатов** — легитимный трюк у всех (roy 150 гвоздей/итер.,
   Demoussel пачки по 5000, наш `-r ~50` из оригинального README).
10. **Физика ≠ симуляция.** callummcdougall: для физических работ ≤3500 линий, «реальная
    нить плотнее симуляции»; kaspar98/ReString RGB: порядок нитей не экспортируется из-за
    аддитивного смешивания. roy-hachnochi решает мультиколор в CMY-пространстве
    мультипликативно (через логарифм).

## 4. Что это значит для ReString

**Уже совпадаем с практикой:** жадный квадратичный критерий (= kaspermeerts/damione1-L2),
AA-линии (`line_aa` ≈ Xiaolin–Wu у damione1), клип-модель Birsak, `-r` субсэмплинг,
3-неудачи-стоп ∈ семейство стагнаций, 211 гвоздей и насыщение 3400–5700 нитей — консенсус;
наш анализ «сила экспорта ↔ число нитей» независимо переоткрывает вывод Demoussel про
полупрозрачную нить.

**Кандидаты на внедрение (по цене/эффекту):**

1. **`MIN_DISTANCE` между гвоздями хорды** (дёшево, чистое качество) — у нас сейчас
   возможны бесполезные короткие хорды.
2. **Совместить рабочую и экспортную силу** (дефолт `-s 0.05` при больших `-l` или
   автоскейл `-s` от `-l`) — устраняет деградацию рендера, подтверждено и нашей
   калибровкой, и Demoussel.
3. **Затемнение входа ×0.5–0.7** вместо текущего `rgb2gray(img) * 0.9` (Birsak: RMS
   0.137→0.097 при c=0.9→0.5).
4. **Важностная маска** (глаза/рот/лицо) — большой визуальный выигрыш для портретов,
   причём у нас уже есть тест-фикстуры портретов для измерения эффекта.
5. **Откат к лучшему префиксу** при остановке по стагнации (damione1) — прямо ложится на
   наш префикс-детерминизм из quality_analysis.
6. **Блюр-SSIM** в приёмочных тестах вместо «голого» SSIM (isandrocks: σ=2 перед метрикой).
