# Оптимизация: анализ качества программы и ускорение

Задача: изучить качество программы, оптимизировать, перевести на Python 3.14+,
минимизировать зависимости, горячий цикл вынести в Rust (PyO3).

## Итог одной таблицей

| Метрика | До (Py3.12, skimage+matplotlib) | numpy-путь | **Rust-ядро** |
|---|---|---|---|
| CLI, 300 нитей (300×300, 211 гвоздей) | 3.63 с | 1.10 с | **0.41 с** (8.8×) |
| Жадный цикл, 7000 итераций | 74.8 с | 12.4 с | **0.91 с** (82×) |
| Время на итерацию (300×300) | 10.7 мс | ~1.7 мс | ~0.12 мс |
| Полный тест-сьют (40 тестов) | ~70 с* | 43 с | **14.8 с** |
| Runtime-зависимости | 25 пакетов (5 библиотек) | 2 | **2** (numpy + pillow) |
| Python | 3.12 | 3.14 | **3.14** (numpy 2.5) |

\* на исходном стеке сьют содержал 34 теста; 40 — с Rust-эквивалентностью.

## Диагноз: где программа теряла время

cProfile прогона на 300 нитей (5.0 с, до оптимизации):

| Функция | Время | Доля |
|---|---|---|
| `skimage.draw.line_aa` — 63 900 вызовов | 2.32 с | 46% |
| `find_best_nail_position` (Python-цикл) | 0.69 с | 14% |
| `get_aa_line` (обёртка) | 0.37 с | 7% |

Вывод: ~90% времени — не математика, а Python-оверхед. Каждая итерация
заново растризовала **все 211 линий-кандидатов**, хотя каждая пара гвоздей
встречается в среднем 30+ раз за прогон.

## Что сделано

### 1. Векторизация жадного скана (numpy-путь, остаётся fallback'ом)
- **Кэш линий**: все пары гвоздей растризуются один раз за прогон, CSR-структура
  (`bounds/starts`), ~80 МБ при 211 гвоздях.
- **Скан кандидатов** — 6 векторных операций: gather → clip → квадраты ошибок →
  cumsum → разности сегментов → argmax (последний-максимум — та же семантика
  тай-брейка, что у исходного `>=`-цикла). Подмножества `-r` считаются через
  cumsum-разности (наивный reduceat по отфильтрованным границам суммирует
  «через головы» — поймано отладкой против грубой силы).
- RGB-каналы делят один кэш (3× → 1× сборки).

### 2. Собственные растризаторы — бит-совместимые с оригиналом
- `line_aa` — точный порт **Zingl-алгоритма** из skimage (BSD): пиксели
  идентичны, значения совпадают до 1 ulp (380/500 побитово, остальные —
  2.2e-16 на float-делении). Первая попытка (классический Xiaolin–Wu)
  оказалась «тоньше» (300 пикселей против 396 на отрезке) и перетемняла
  рендер — пороговые тесты поймали это, реализация переписана по исходнику.
- `ellipse_perimeter` — midpoint-алгоритм: **100% совпадение множества
  пикселей** с skimage на всех тестовых сетках (844/844, 276/276, 176/176).
- `resize` — box area-фильтр (даунскейл, corr 0.9998 против skimage) +
  билинейный (апскейл; box при апскейле давал блочные ступени — поймано
  синтетическими e2e-тестами).
- I/O — Pillow; SSIM — свой (uniform-окно) в `restring.metrics`.
- **Итог: scikit-image и matplotlib полностью покинули зависимости.**

### 3. Python 3.14 + numpy 2
`requires-python >=3.14`, numpy 2.5, pillow 13; lock сократился с 25 до 9
пакетов, runtime — **numpy + pillow**. Сьют на 3.14 стал быстрее сам по себе
(70 → 43 с).

### 4. Rust-ядро `restring._core` (PyO3, abi3)
- `line_aa` + весь жадный цикл на Rust: кэш линий строится за ~40 мс,
  итерация ~0.12 мс, канвас живёт в `Vec<f64>` без GIL.
- `generator.create_art` автоматически использует `_core` (fallback —
  numpy-путь, если расширение не собрано).
- Подмножество `-r` рисуется на Python стороне тем же `default_rng(42)` —
  оба бэкенда видят одинаковых кандидатов.

## Эквивалентность (тесты `tests/test_rust_core.py`)

- `line_aa`: **300/300** точных совпадений Rust↔Python на случайных отрезках
- Порядок нитей на 7000 итераций: **2862/2862 (100%)** — жадный выбор не
  «дрейфует» между бэкендами; итоговый MSE совпадает (0.06866)
- Рабочий канвас: идентичен с точностью 1e-9
- Подмножества `-r`: порядки идентичны
- Детерминизм: два прогона — байт-в-байт

## Сборка

`uv sync` собирает расширение maturin'ом автоматически. На машинах без
системного `cc` (минимальные WSL/контейнеры) работает линкер через zig:

```bash
curl -sL https://ziglang.org/download/0.17.1/zig-x86_64-linux-0.17.1.tar.xz | tar -xJ -C ~/.local/zig --strip-components=1
printf '#!/bin/sh\nexec ~/.local/zig/zig cc "$@"\n' > ~/.local/bin/zigcc && chmod +x ~/.local/bin/zigcc
export CARGO_TARGET_X86_64_UNKNOWN_LINUX_GNU_LINKER=~/.local/bin/zigcc
uv sync
```

Без Rust-тулчейна пакет продолжает работать на numpy-пути (расширение
опционально, скорости из таблицы колонка 2).

## Воспроизведение бенчмарков

```bash
uv run python -c "
import time
from restring.canvas import init_canvas
from restring.generator import create_art
from restring.nails import create_circle_nail_positions
from restring.image_transformations import resize, largest_square, rgb2gray
import numpy as np; from PIL import Image
img = np.asarray(Image.open('tests/data/portrait_male.png').convert('RGB'), dtype=float)/255
ref = rgb2gray(resize(largest_square(img), (300,300)))*0.9
nails = create_circle_nail_positions((300,300), nail_step=4)
t0=time.perf_counter()
o = create_art(nails, ref, init_canvas((300,300)), -0.05, i_limit=7000)
print(f'7000 iters: {time.perf_counter()-t0:.2f}s')
"
```
